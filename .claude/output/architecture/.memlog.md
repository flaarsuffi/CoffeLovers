# CoffeLovers Architecture Memlog

**Scope:** Framework selection and initial architecture for CoffeLovers premium coffee website  
**Purpose:** Establish build substrate for SSG conteúdo site (Phase 1) with evolution path to future features  
**Altitude:** Initiative  
**Status:** in-progress  

---

## Decisions

- **decision**: Framework = Next.js 14+ with TypeScript
  - **Binds**: React as UI paradigm; App Router (file-based routing); SSG at build-time for static content; TypeScript for type safety
  - **Prevents**: Divergence on JS framework choice; mismatched tooling between dev and static build
  - **Why**: Starts with zero-JavaScript SSG (graos/metodos pages generated at build), scales to dynamic APIs (shop/recommendations) later. TypeScript for maintainability as codebase grows. Single codebase evolution path.
  - **Status**: [ADOPTED] — user confirmed

- **decision**: Rendering strategy = Static Site Generation (SSG) for Phase 1
  - **Binds**: All pages (homepage, grão detail, método detail) generated at build-time from JSON data in `conteudo/`
  - **Prevents**: Runtime data fetching overhead on mobile; per-request rendering
  - **Why**: Conteúdo is static (7 grãos + 5 métodos). Mobile performance critical. Pure HTML/CSS delivery = instant loads.
  - **Status**: [ADOPTED]

- **decision**: Styling = Tailwind CSS (utility-first)
  - **Binds**: Design tokens from DESIGN.md mapped to Tailwind config (colors, spacing, typography, etc). Component classes in TSX files.
  - **Prevents**: Mismatched spacing/colors between team members; design drift
  - **Why**: Design.md already specifies tokens (colors, spacing, rounded, shadows). Tailwind codifies these as config. Utility-first matches compact, refined aesthetic.
  - **Status**: [ADOPTION PENDING] — will refine in architecture spine

- **decision**: Image optimization = Next.js Image component + Vercel/external CDN
  - **Binds**: 12 3D renders (graos/ and metodos/) served via optimized Image component (AVIF, WebP fallback, lazy loading)
  - **Prevents**: Unoptimized PNGs bloating mobile loads
  - **Why**: Assets already exist (1200x1200px). Image component auto-resizes, formats for device. Mobile-critical.
  - **Status**: [ADOPTION PENDING]

- **decision**: Content structure = JSON in `conteudo/` → TypeScript types → build-time page generation
  - **Binds**: graos.json and metodos.json live at project root (or `/lib/data`). generateStaticParams() per [id] route. No runtime file I/O.
  - **Prevents**: Data fetch bottlenecks; content/code desync
  - **Why**: Data is immutable at build time. Generates /graos/bourbon, /graos/catuai, etc. as static HTML.
  - **Status**: [ADOPTED]

- **decision**: Animations = CSS transitions + `prefers-reduced-motion` respect + conditional JS
  - **Binds**: Hover states (card translateY, color shifts) defined in Tailwind/CSS. Desktop gets smooth transitions; mobile gets instant (via media query or JS gate). Respects OS accessibility setting.
  - **Prevents**: Animation jank on mobile; accessibility violations
  - **Why**: User said "subtle, important to work well on mobile; animations OK on desktop if no perf hit"
  - **Status**: [ADOPTED]

- **direction**: Shop/recommendations = Deferred, not Phase 1
  - **Why**: User clarified shop is "future distante". Phase 1 is conteúdo só.
  - **Prep**: API routes folder created but empty. Database/auth decisions deferred.

- **assumption**: Vercel as deployment target
  - **Why**: Natural fit for Next.js. Auto-CDN, image optimization, environment setup trivial.
  - **Risk**: If user wants self-hosted later, need to adjust image strategy.
  - **Status**: [PENDING CONFIRMATION]

- **question**: Internationalization (i18n)?
  - **Why**: Site is Portuguese-first; no mention of English or multi-lang yet.
  - **Deferred?**: Yes, Phase 1 is PT-BR only.

- **question**: Dark mode toggle vs forced dark?
  - **Why**: DESIGN.md shows dark as default/only. CSS and Tailwind ready for dark. Light mode mentioned but not in Phase 1 scope.
  - **Decision**: Phase 1 = dark only. Toggle deferred.
